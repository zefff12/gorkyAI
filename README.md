# Голосовой ассистент для задач и встреч

Прототип ассистента, которому можно сказать или написать в свободной форме:
«Напомни мне завтра в 10 утра позвонить Ивану», «Что у меня на этой неделе?»,
«Когда у меня была встреча с Иваном?», «А перенеси её на понедельник». Он понимает
запрос, при нехватке данных задаёт уточняющий вопрос, сохраняет записи в базу
и отвечает текстом и голосом.

**Демо:** _ссылка на развёрнутый прототип_ · **Репозиторий:** _ссылка_

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  source .venv/bin/activate — macOS/Linux
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000 в Chrome, Edge или Safari, нажмите на микрофон
(или Ctrl+Пробел) и говорите. Можно писать текстом — так работает в любом браузере.

Каждый браузер получает свой случайный ID (поле 👤), поэтому посетители не видят
записей друг друга, и список начинается пустым. 1000 тестовых записей из
`data/voice_assistant_events_1000.csv` загружаются кнопкой «Загрузить тестовые данные
из задания» — она видна, пока список пуст. Чтобы открыть свой список на другом
устройстве, введите там тот же ID. Загрузка CSV пользователю `demo` при старте
включается через `SEED_DEMO=1`.

**Docker:**

```bash
docker build -t voice-assistant .
docker run -p 8000:8000 voice-assistant
```

**Тесты** (131 тест, работают без сети и без ключей; тест настоящей модели эмбеддингов запускается, если задан `MODEL_CACHE`):

```bash
pip install -r requirements-dev.txt
pytest
```

**LLM (необязательно).** Без ключа работает встроенный парсер на правилах,
и все сценарии выполняются. Если задать `ANTHROPIC_API_KEY`, запросы разбирает
Claude, а правила остаются запасным вариантом на случай ошибки сети или API.
Настройки — в `.env.example`.

**Семантический поиск** включён по умолчанию: при первом запуске модель (~240 МБ)
скачивается в фоне, пока поиск работает на лексическом слое. Отключить: `SEMANTIC_SEARCH=0`.

## Что умеет

| Сценарий | Примеры |
|---|---|
| Создать задачу / напоминание | «Напомни завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «Поставь задачу купить билеты до конца недели», «Купить молоко», «Через два часа позвонить маме» |
| Создать встречу | «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с дизайнером», «Созвон с клиентом послезавтра с 14 до 16» |
| Список на период | «Что у меня сегодня?», «Какие планы на сегодня?», «Покажи мои встречи на сегодня», «Какие задачи на завтра?», «Что запланировано на эту неделю?», «…на следующей неделе / на выходных / в этом месяце / 20 октября» |
| Поиск старых записей | «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?», «Я когда-то ставил задачу по договору, найди её», «Были ли встречи с Альфой?» |
| Уточняющий диалог | «Поставь встречу с Иваном завтра» → «На какое время поставить встречу завтра?» → «в 12»; «Купить подарок» → «Когда и во сколько нужно «Купить подарок»?» → «в субботу» → «Во сколько в субботу?» → «в течение дня» |

### Дополнительные возможности из задания

| Пункт задания | Как работает |
|---|---|
| Изменение и удаление задач голосом | «Перенеси встречу с Иваном на 17:00», «Измени время встречи на 15:30», «Переименуй её в Созвон с Иваном», «Измени название задачи про отчёт на …», «Удали встречу с дизайнером» (с подтверждением «да») |
| Отметка выполненной | «Отметь её выполненной», «Я сделал задачу про отчёт». В списках видно ✓ |
| Конфликтующие встречи | «В это время у вас уже есть встреча «…» в 15:00. Всё равно добавить?» — можно ответить «да» или назвать другое время («давай на 14:30»). Проверяется и при переносе |
| Повторяющиеся задачи и встречи | «Каждый понедельник в 10 планёрка», «по будням в 10 стендап», «ежедневно». Показываются во всех периодах |
| Контекст диалога | «А перенеси её на завтра», «Отметь её выполненной», «Переименуй её…» — действие применяется к последней записи, о которой шла речь |
| Семантический поиск | Гибрид: лексический слой (леммы, синонимы, нечёткое совпадение для ошибок распознавания, BM25) + эмбеддинги предложений (многоязычная модель MiniLM, локально на CPU). «Слайды для выступления» → «Подготовить презентацию», «отзывы» → «Собрать обратную связь», «деньги» → «Обсудить бюджет», «контракт» → «договор» |
| Несколько пользователей | У каждого свои записи и контекст диалога. Браузер сам получает случайный ID, его видно в поле 👤; в API — заголовок `X-User-Id` |
| Неоднозначные запросы и уточняющий диалог | Не хватает времени или дня — ассистент спрашивает. Под запрос подходят несколько записей — показывает нумерованный список («Какую перенести? 1) … 2) …») и понимает «вторую». Новая команда во время уточнения не теряется |

Относительные даты: сегодня, завтра, послезавтра, в пятницу, в следующую пятницу,
через 2 часа, через полчаса, через неделю, на следующей неделе, до конца недели,
к пятнице, 20 октября, 15.11, «двадцать третьего ноября», «в 3 дня», «в 7 вечера»,
в полдень, утром/вечером, «с 14 до 16».

## Архитектура

```
 Браузер                                   Сервер (FastAPI)
┌──────────────────────────┐  POST /api/message  ┌──────────────────────────────────────────┐
│ микрофон → Web Speech STT ├────── текст ───────►│ main.py        HTTP, пользователи         │
│ история диалога           │                     │   │                                      │
│ ответ → speechSynthesis   │◄── text + speech ───┤ assistant.py   диалог и бизнес-логика   │
│ панель «ближайшие 7 дней» │    + events         │   │  ├─ уточнения (pending)              │
└──────────────────────────┘                     │   │  ├─ контекст (last_ids)              │
                                                  │   │  └─ пересечения, подтверждения       │
                                                  │   ├─ nlu/llm.py    Claude → ParsedCommand │
                                                  │   ├─ nlu/rules.py  правила → ParsedCommand│
                                                  │   │    └─ nlu/dates.py, nlu/text.py       │
                                                  │   ├─ search.py     гибридный поиск        │
                                                  │   │    └─ semantic.py  эмбеддинги         │
                                                  │   └─ storage.py    SQLite                 │
                                                  └──────────────────────────────────────────┘
```

Слои разделены так, как просит задание:

- **Голос** — только в браузере (`static/app.js`). Сервер получает и отдаёт текст. Чтобы подключить другой STT/TTS, достаточно поменять фронтенд.
- **Понимание (NLU)** — `app/nlu/`. И LLM, и правила возвращают одну структуру `ParsedCommand` (интент, тип, название, дата, время, период, запрос, ссылка на контекст). LLM ничего не делает с данными сама: она только разбирает фразу.
- **Бизнес-логика** — `app/assistant.py`. Детерминированный код решает, хватает ли данных, что спросить, есть ли пересечения, какую запись менять. Его легко тестировать.
- **Хранение** — `app/storage.py`. SQLite, одна таблица `events`. Модуль ничего не знает о языке.

| Файл | Что делает |
|---|---|
| `app/models.py` | `Event`, `ParsedCommand`, перечисления |
| `app/nlu/text.py` | токенизация, числительные словами → цифры, лемматизация (pymorphy3) |
| `app/nlu/dates.py` | относительные даты, время, периоды, сроки, повторы |
| `app/nlu/rules.py` | интент по леммам, тип записи, сборка названия |
| `app/nlu/llm.py` | Claude с принудительным tool call и JSON-схемой |
| `app/search.py` | гибридный поиск: BM25 по леммам, синонимы, нечёткое совпадение + семантический слой; фильтры по типу, времени и периоду |
| `app/semantic.py` | эмбеддинги предложений (fastembed, ONNX, CPU), фоновая загрузка модели, кэш векторов |
| `app/assistant.py` | диалоговый менеджер |
| `app/formatting.py` | «в пятницу, 16 октября», «2 встречи и 3 задачи» |
| `app/seed.py` | импорт CSV |
| `app/main.py` | REST API: `/api/message`, `/api/events`, `/api/stats`, `/api/demo-data`, `/api/reset`, `/api/health` |

## Выбранные технологии и почему

- **Python + FastAPI.** Лучшие инструменты для русской морфологии, мало шаблонного кода, автодокументация API на `/docs`.
- **STT/TTS: Web Speech API браузера.** Бесплатно, без ключей, промежуточные результаты распознавания видны прямо во время речи, хорошо понимает русский. Ограничение: в Firefox распознавания нет, там остаётся текстовый ввод.
- **NLU: гибрид «LLM + правила».** Правила на леммах (pymorphy3) покрывают все сценарии из задания и работают офлайн за миллисекунды. Поэтому прототип можно запустить и проверить без ключей. LLM (Claude Haiku, быстрая и дешёвая) добавляет гибкость на нестандартных формулировках. Даты для неё дополнительно подстрахованы: в промпт передаётся календарь на ±2 недели.
- **SQLite.** Нулевая настройка, данные переживают перезапуск, для одного пользователя и тысяч записей этого с запасом.
- **Поиск: гибридный.** Лексический слой — леммы, словарь синонимов, нечёткое совпадение для ошибок распознавания и BM25-веса, чтобы редкие слова («Иван», «хакатон») весили больше частых («проверить»). Семантический слой — модель `paraphrase-multilingual-MiniLM-L12-v2` через fastembed (ONNX, без PyTorch): ~0,7 с на 1000 записей на CPU, без внешних API и ключей. Семантические совпадения никогда не обгоняют точные: имя «Иван» должно найти именно Ивана, а не «похожих» людей. Плюс фильтры: «задачу» → только задачи, «была» → только прошлое.

## Решения, принятые самостоятельно

- **Данные из CSV.** В файле нет типа записи, поэтому тип определяется по тексту: «Встреча…», «Созвон…», «Демо…», «Провести планёрку…» и «Обсудить X с <человеком>» — это встречи, «Напомнить…» — напоминания, остальное — задачи (232 / 53 / 715). В сгенерированных текстах неверные падежи («Позвонить Иваном», «Напомнить Анной про аналитике»). При импорте они исправляются («Позвонить Ивану», «Напомнить Анне про аналитику»), чтобы ассистент нормально зачитывал записи. Исходная строка сохраняется в `source_text`.
- **Обязательность полей.** Встрече нужны и день, и время, иначе ассистент спросит. Напоминанию нужно время. Для задачи ассистент спрашивает «Когда и во сколько?» или «Во сколько завтра?». Можно ответить «без срока» или «в течение дня». Не спрашивает, если дата — это срок («до конца недели», «к пятнице»), и для повторяющихся задач. Если названо только время, и оно сегодня уже прошло, запись ставится на завтра.
- **«В пятницу»** — ближайшая пятница. Если пятница сегодня и названное время уже прошло — следующая. **«В следующую пятницу»** — пятница следующей недели. **«В 3»** без уточнения — 15:00: в деловом контексте так почти всегда. **«До конца недели»** — воскресенье.
- **Деструктивные действия подтверждаются.** Удаление требует «да», пересекающаяся встреча тоже.
- **Ответ для экрана и для голоса разный.** На экране полный список, вслух — первые 5 пунктов и «и ещё N — смотрите на экране».
- **Если во время уточнения пользователь говорит новую команду,** уточнение отменяется и выполняется новая команда. Ассистент не застревает в вопросе.

## Что бы я улучшил при наличии времени

- Серверное распознавание речи (Whisper или Yandex SpeechKit), чтобы голос работал во всех браузерах, и более естественный нейросетевой голос.
- Хранить векторы в базе (sqlite-vec / pgvector), чтобы не пересчитывать их после перезапуска.
- Настоящие уведомления о напоминаниях (Web Push или Telegram-бот) — сейчас напоминание только сохраняется.
- Интеграция с Google Calendar / CalDAV.
- Авторизация вместо идентификатора в заголовке и PostgreSQL для многопользовательского продакшена.
- Изменение отдельных вхождений повторяющихся событий (сейчас серия переносится целиком).
- Офлайн-набор фраз с метриками качества разбора, чтобы сравнивать правила и LLM на одних данных.

## Деплой

Есть `Dockerfile` и `render.yaml`. На Render.com: New → Blueprint → репозиторий.

- **Память.** Сервер с моделью семантического поиска занимает ~770 МБ, а на бесплатном тарифе Render доступно 512 МБ. Поэтому в `render.yaml` стоит `SEMANTIC_SEARCH=0`: модель не скачивается, поиск работает на лексическом слое (леммы, синонимы, ошибки распознавания). На тарифе Starter (2 ГБ) и выше можно поставить `1`.
- **Данные.** На бесплатном тарифе диск временный, а сервис засыпает после 15 минут без запросов. После пробуждения или перезапуска записи пропадают. Для постоянного хранения нужен платный диск Render (`DB_PATH` на него) или внешняя база.
- **Ключ Claude** (`ANTHROPIC_API_KEY`) необязателен: без него работают встроенные правила.
